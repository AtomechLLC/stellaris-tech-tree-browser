Real-file ground truth (measured 2026-08-18, planner probe):
- 183 top-level entries found by the brace-depth scanner; jomini reports only 182 top-level keys,
  because the name "Cyrrician Core" appears TWICE and jomini collapses the duplicate into an array
  of length 2. Reconciliation must sum array lengths, not count keys.
- Line endings are CRLF. The separator between every adjacent pair of entries is exactly "\r\n"
  (183 spans, one distinct gap value), the first span starts at offset 0, and the file ends with a
  single trailing "\r\n" after the last closing brace.
- UTF-8: decode with `{ fatal: true }` then re-encode round-trips byte-identically. The only
  non-ASCII sequence is U+202F.
- 7 entry names contain raw 0x11 Paradox colour-escape bytes; those bytes are part of the game's
  identity key for the entry.

Existing helper contracts this plan builds beside (do not duplicate, do not modify):
- `app/src/lib/pdxText.ts` exports `parsePdxText(raw: string): PdxSegment[]` and
  `stripPdxCodes(raw: string): string`.
- `app/src/lib/empire/savLoad.ts` throws plain `Error` with a user-facing message on bad input;
  `EmpirePanel.tsx` surfaces it via `e instanceof Error ? e.message : String(e)`.

  <action>
    Create `app/src/lib/empire/designsText.ts`, the D-08 engine. This module is the ONLY code path allowed
    to produce designs-file output, and it produces it exclusively by slicing the original decoded text.

    Exports:

    `EntrySpan` = `{ name: string; start: number; end: number }` where `start` is the index of the opening
    quote of the entry name and `end` is one past the matching top-level closing brace.

    `findTopLevelSpans(text: string): EntrySpan[]` — implement the quote-aware brace-depth scanner from
    RESEARCH.md Pattern 1 verbatim in behavior: skip whitespace, require a `"` (otherwise stop, do not guess),
    capture the raw name bytes between the quotes without any code-stripping, advance to `{`, then track
    `inQuotes` toggling on `"` and depth on unquoted `{`/`}` until depth returns to 0. There are no
    backslash-escaped quotes in this format (verified against the real 400KB file). If the loop reaches
    end-of-text while depth is still greater than 0, that is a malformed file — surface it (see `parseDesignsFile`).

    `decodeDesignsBytes(bytes: Uint8Array): { text: string; encoding: "utf-8" | "windows-1252"; warning: string | null }`
    — decode with `new TextDecoder("utf-8", { fatal: true })` first (RESEARCH Pitfall 1: the designs file is
    UTF-8, NOT windows-1252 like the .sav); on a thrown decode error fall back to `new TextDecoder("windows-1252")`
    and return a warning string explaining that the file was not valid UTF-8 and was read as windows-1252
    (RESEARCH Assumption A1's recommended mitigation). Strip a leading U+FEFF if present.

    `encodeDesignsText(text: string): Uint8Array` — `new TextEncoder().encode(text)`.

    `DesignsEntry` = `{ rawName: string; displayName: string; start: number; end: number; authority: string | null;
    speciesClass: string | null }`. `rawName` is the exact bytes between the quotes and is the identity used for
    D-09 collision checks; `displayName` is `stripPdxCodes(rawName)` from `app/src/lib/pdxText.ts` and is for UI only.

    `DesignsFile` = `{ filename: string; text: string; separator: string; encoding: "utf-8" | "windows-1252";
    entries: DesignsEntry[]; warning: string | null }`.

    `parseDesignsFile(bytes: Uint8Array, filename: string): Promise<DesignsFile>` — decode, run
    `findTopLevelSpans`, then lazily `Jomini.initialize()` (cache the instance in a module-level variable
    exactly like `savLoad.ts` does) and `parser.parseText(text, { encoding: "utf8" })`. No `__root__` wrapper is
    needed for this file — unlike the gamestate, every top-level construct here is already a key=value pair.
    Reconcile: the span count MUST equal the sum over the parsed object's own keys of (value array length when
    `Array.isArray(value)`, else 1). This exact rule is load-bearing — the user's real file has 183 spans but
    only 182 jomini keys because the name "Cyrrician Core" appears twice and jomini collapses duplicates into an
    array. A naive `Object.keys().length === spans.length` check would reject the user's own file. On mismatch,
    on an unterminated block, or on a non-quote leading character, `throw new Error(...)` with the
    UI-SPEC's copy: "Couldn't read this file — it doesn't look like a Stellaris empire designs file. Check you
    picked the right file and try again." Per-entry `authority`/`speciesClass` for the UI list come from the jomini
    parse (`authority` scalar; `species.class`), read defensively with `isObj`/`toArr` guards and defaulting to null;
    match a span to its parsed value by name, taking the array element at the duplicate-occurrence index when the
    parsed value is an array.

    Detect and store `separator`: the exact text between the end of span N and the start of span N+1 when there
    are 2+ entries (verified to be a single "\r\n" throughout the real file); when there are fewer than 2 entries,
    use "\r\n" if the text contains "\r\n" and "\n" otherwise. Never hardcode "\n" — the real file is CRLF and a
    "\n" join silently rewrites every line ending in the file.

    `spliceDesignsFile(file: DesignsFile, removedIndices: ReadonlySet<number>, addedTexts: readonly string[]): string`
    — build the output as: for each entry index not in `removedIndices`, `file.text.slice(entry.start, entry.end)`;
    then each string in `addedTexts` in order; join all pieces with `file.separator` and append `file.separator`
    at the end. Never re-serialize a kept entry, never touch its bytes, never trim it. This same function is what
    the archive file goes through (RESEARCH Pitfall 6 — the archive's existing entries get the identical protection).

    `uniqueDesignName(desired: string, taken: Iterable<string>): string` — D-09. If `desired` is not in `taken`,
    return it unchanged; otherwise append " (2)", " (3)", ... until free. Compare RAW strings only — never strip
    Paradox colour codes for this comparison (the game keys designs by the literal bytes including 0x11 escapes);
    `stripPdxCodes` is display-only.

    Then create `app/src/test/designsText.test.ts` covering every case in the behavior block above, using inline
    string fixtures in the `empire-classify.test.ts` style. Do NOT check in or depend on the user's real 400KB file.
    Build any control-byte fixture with `String.fromCharCode(0x11)` so no invisible literal lands in the source
    (same discipline as `pdxText.ts` lines 32-35). Fixtures must use real tab-indented, CRLF-terminated entry text
    so the round-trip assertions are meaningful.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user file → app memory | An uploaded `.txt` is fully untrusted input: it may be a different file entirely, truncated, or a different encoding |
| app memory → output bytes | Everything written back to the user's disk originates here; a defect here is user data loss |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `parseDesignsFile` (untrusted uploaded .txt) | mitigate | jomini structural parse inside try/catch + span/entry-count reconciliation (array-aware); any mismatch throws the UI-SPEC error instead of returning a partial file. Scanner stops rather than guessing when the leading character is not a quote. |
| T-04-02 | Tampering | `spliceDesignsFile` (output construction) | mitigate | Kept entries are emitted as raw `text.slice(start, end)` — no serializer is reachable from this path (enforced by the grep gate in acceptance criteria). Round-trip identity test on CRLF and LF fixtures. |
| T-04-03 | Tampering | `uniqueDesignName` (D-09 collision key) | mitigate | Collision comparison uses raw name bytes including 0x11 colour escapes; `stripPdxCodes` is never applied on this path, so a crafted colour-coded name cannot alias onto another entry's identity. |
| T-04-04 | Information disclosure | designs file contents | accept | All parsing is in-browser, no network call exists in this module or anywhere in the phase (static SPA, no server per CLAUDE.md). |
| T-04-SC | Tampering | npm installs | mitigate | No packages are installed by this plan or this phase — `jomini` and `fflate` are pre-existing `app/` dependencies (RESEARCH.md Package Legitimacy Audit: not applicable).
