<objective>
Map a save's `country` / `species_db` / `leaders` / `planets` / `galactic_object` tables onto the
`DesignEntry` contract, and attach the result to every `SavedEmpire` the existing loader already produces,
so "add to my empires" (04-07) has a complete, game-loadable payload for any empire in the save (D-06/D-07).

Purpose: this is the mapping half of the phase — mostly 1:1 field renames plus three genuinely tricky
resolutions (ruler, founder species, planet class).
Output: `designFromSav.ts`, `SavedEmpire.design`, `designFromSav.test.ts`.
</objective>

Sample-save facts (133 countries, 325 species_db entries, 2081 leaders):
- `country.room` IS present on the country — but only on 70 of 133. Fallback `"default_room"` is required.
  (Resolves RESEARCH Open Question 2 / assumption A3.)
- `country.is_nomadic` IS present on 7 of 133. Read it when present, default false. (Resolves A5.)
- `country.advisor_voice_type` present on 6 of 133 — omit the field entirely when absent.
- `country.ship_prefix` present on only 14 of 133 — needs a default of `{ key: "ISS" }`.
- `country.flag` has the design file's `empire_flag` shape but its `colors` array can be shorter than 6
  (observed 4). Padding is the serializer's job (04-03), not this module's.
- `country.founder_species_ref` DOES index `species_db` directly even though the id is large and tagged
  (observed 536870913, and `"536870913" in species_db` is true).
- `species_db[id]` shape: `{ name, plural, adjective, class, portrait, name_list, gender, traits: { trait: [...] }, home_planet: { type, reference } }`.
  `traits` can be an EMPTY OBJECT `{}` for degenerate species — guard with `toArr`.
- `country.ruler` is a numeric leader id into `root.leaders` (an object with numeric string keys).
  Only 29 of 2081 leaders carry a `design` snapshot, and the sampled player empire's own current ruler
  does NOT — the synthesize path is the common path, not the edge case (confirms RESEARCH Pitfall 4).
- A leader `design` snapshot has exactly the design file's `ruler` shape:
  `{ gender, name: { full_names, use_full_regnal_name }, portrait, texture, evolution_mask, attachment, clothes, trait, leader_class }`.
- A leader without `design` carries `name` (already in `full_names` LocName shape), `portrait`, `gender`,
  `class`, and a `traits` array mixing `subclass_*` and `leader_trait_*` entries — e.g.
  `["subclass_official_economy_councilor", "leader_trait_reformer_2", ...]`. The design's single `ruler.trait`
  should be the first entry prefixed `leader_trait_`.
- Leader design snapshots carry NUMERIC `variables[].key` values (`key: 1`) where the designs file writes
  `key="1"` — `parseLocName` (04-01) already normalizes this; route every LocName through it.
- `country.capital` is present on only 81 of 133, and for the sampled player empire it resolves to
  `planets.planet[0].planet_class === "pc_b_star"` — a STAR. Copying it blindly is wrong (RESEARCH Pitfall 5,
  now confirmed on a normal empire rather than a degenerate one).
- System name resolution that works: `planets.planet[capital].coordinate.origin` gives a `galactic_object`
  id whose `.name` is a LocName.

Existing code contracts:
- `app/src/lib/empire/savLoad.ts` exports `SavedEmpire extends RawEmpire` with `{ id, name, playerName, researchedCount }`,
  and computes per-country `ethics` (with a pop-group fallback closure `speciesEthicsFor`) inside `loadEmpiresFromSav`.
  Helpers `toArr` / `isObj` are defined at lines 60-65.
- `app/src/lib/empire/designSchema.ts` (04-01) exports `DesignEntry`, `DesignSpecies`, `DesignRuler`,
  `DesignFlag`, `LocName`, `parseLocName`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uploaded `.sav` → design payload | The save is untrusted input: every field may be absent, a different type, or contain control bytes and quotes |
| design payload → user's designs file | Whatever this module emits is eventually written into a real user data file by 04-06 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-11 | Tampering | `extractDesignFromCountry` reading untrusted save tables | mitigate | Every read goes through `isObj`/`toArr` guards with an explicit fallback; no bare `as` casts. A country lacking `government` returns `null` rather than a half-built entry. |
| T-04-12 | Integrity (game-loadability) | ruler resolution | mitigate | Both branches (`design` snapshot present / synthesized) produce a complete ruler block; a missing leader still yields defaults. Both branches are exercised by tests, so neither is an untested path. |
| T-04-13 | Integrity (game-loadability) | `planet_class` from `country.capital` | mitigate | Explicit habitable allowlist with `pc_continental` fallback; the measured `pc_b_star` case is a committed test, so the guard cannot be silently removed. |
| T-04-14 | Tampering | control bytes / quotes in save-derived names | transfer | Sanitization is owned by `serializeDesignEntry` (04-03, threat T-04-08) at the single point where strings become file text; this module deliberately preserves raw bytes so display and identity stay faithful. |
| T-04-SC | Tampering | npm installs | mitigate | Nothing installed; `jomini`/`fflate` are pre-existing dependencies. Any `npm install` during execution stops for human review. |
