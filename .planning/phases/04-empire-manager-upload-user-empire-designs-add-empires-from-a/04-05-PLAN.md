    Create `app/src/lib/empire/useDesignsSession.ts` exporting a React hook `useDesignsSession(): DesignsSession`
    plus the `DesignsSession` and `StagedAdd` types. This hook owns all Empire Manager state so that state
    survives the dialog being closed (UI-SPEC Dialog Close Behavior: closing must never discard staged work).

    `StagedAdd` = `{ id: string; rawName: string; originalName: string; text: string; sourceEmpireId: number }`
    where `text` is the already-serialized entry body and `rawName` is the possibly-disambiguated name
    (04-07 populates these; this plan only stores and counts them).

    `DesignsSession` exposes state: `designs: DesignsFile | null`, `archive: DesignsFile | null`,
    `handle: FileSystemFileHandle | null`, `canWriteInPlace: boolean`, `loading: boolean`,
    `error: string | null`, `warning: string | null`, `removed: ReadonlySet<number>`, `adds: StagedAdd[]`,
    `pendingCount: number` (adds.length + removed.size), plus `takenNames: string[]` (raw names currently in
    the file minus staged removals plus staged adds) for 04-07's D-09 check.

    And actions: `loadDesignsFile(file: File)`, `loadDesignsViaPicker()`, `loadArchiveFile(file: File)`,
    `toggleRemove(index: number)`, `stageAdd(add: StagedAdd)`, `undoAdd(id: string)`, `discard()`,
    `clearError()`.

    Behaviour requirements:
    - `loadDesignsFile` reads `await file.arrayBuffer()`, wraps in `Uint8Array`, and calls
      `parseDesignsFile` obtained through a dynamic `await import("./designsText")` inside the handler so
      jomini stays out of the main bundle (mandatory per CLAUDE.md's bundle constraint and RESEARCH.md).
      Set `loading` true/false around it in a try/catch/finally, and on failure set `error` to
      `e instanceof Error ? e.message : String(e)` and leave the previously loaded file untouched.
    - On success, replace `designs`, clear `removed` and `adds`, clear `error`, and copy
      `DesignsFile.warning` into `warning` (the windows-1252 fallback notice from 04-01).
    - `loadDesignsViaPicker` calls `pickTextFileHandle()`; a null result (unsupported or user cancelled)
      is a no-op with no error. Otherwise read the file via `handle.getFile()`, parse it the same way,
      store the handle, and set `canWriteInPlace` from `await ensureReadWritePermission(handle)`.
      Never let an unsupported browser reach a dead end (D-02).
    - `loadArchiveFile` parses through the same `parseDesignsFile` path (D-08's "same rule for the uploaded
      archive file"), stores it in `archive`, and surfaces its own parse error without discarding the
      loaded designs file.
    - `toggleRemove` adds/removes an index in an immutable new `Set`.
    - `discard()` clears `removed` and `adds` only — it never clears the loaded file or the handle.
    - Filenames are never hardcoded: `DesignsFile.filename` is whatever the user provided (D-03). Do not
      match on, validate against, or reconstruct `user_empire_designs_v3.4.txt` anywhere in this module.
    - No `save()` in this plan — 04-06 adds it.

    Keep this module free of JSX so it stays a plain `.ts` file, and keep every returned action wrapped in
    `useCallback` so `EmpirePanel`'s existing effects are not re-triggered by identity churn.
  </action>
