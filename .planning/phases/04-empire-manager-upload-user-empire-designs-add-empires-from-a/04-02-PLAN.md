<objective>
Build the browser file-I/O layer this phase needs: one shared `downloadBlob` (D-01 baseline, used by the
designs file, the archive file and the pre-write backup), and a File System Access wrapper that makes
D-02's "backup before any in-place write" a property of the function signature rather than a convention
the UI could forget.

belongs in the I/O layer, not in a component.

    Export:

    `downloadBlob(data: Uint8Array | Blob, filename: string, mimeType?: string): void` — the shared helper.
    Lift the exact idiom from `mapImage.ts` lines 124-131 (create object URL, `<a>` with `href`/`download`,
    `.click()`, `URL.revokeObjectURL`). Default mime type `"text/plain;charset=utf-8"`; when handed a Blob use
    it as-is. This is the D-01 baseline path and has three call sites in this phase (designs file, archive
    file, pre-write backup) plus `mapImage.ts`.

    `supportsFsAccess(): boolean` — `"showOpenFilePicker" in self`. Feature-detect at call time (not at module
    load) so it is trivially stubbable, and per D-02 never treat absence as an error state.

    `pickTextFileHandle(): Promise<FileSystemFileHandle | null>` — returns null immediately when
    `supportsFsAccess()` is false. Otherwise call `showOpenFilePicker` with a `.txt` text/plain accept entry
    and `multiple: false`, and return the first handle. A user cancelling the picker throws `AbortError` —
    catch that specific case and return null (cancelling is not an error the UI should surface); rethrow
    anything else as a plain `Error`.

    `ensureReadWritePermission(handle: FileSystemFileHandle): Promise<boolean>` — return true if
    `queryPermission({ mode: "readwrite" })` is already `"granted"`, else return whether
    `requestPermission({ mode: "readwrite" })` resolves to `"granted"`. Never throw for a denial —
    return false so the caller can fall back to the download path (UI-SPEC "Failure (permission denied
    mid-write)" requires an automatic fallback, never a stuck state).

    `backupFilename(originalFilename: string, at: Date): string` — pure, per the behavior block.

    `saveInPlaceWithBackup(handle, originalBytes, newBytes, originalFilename, at?): Promise<{ backupName: string }>`
    — the D-02 safety ordering encoded in one function so no caller can skip it:
    (1) call `downloadBlob(originalBytes, backupFilename(originalFilename, at ?? new Date()))` FIRST and
    unconditionally; (2) only then `await handle.createWritable()`, `write(newBytes)`, `close()`;
    (3) return the backup name so the UI can render the success-banner sentence
    "Backup downloaded as `{originalFilename}.{timestamp}.bak`." Add a comment stating that steps 1 and 2 must
    not be reordered and that `originalBytes` must be the bytes as read, not a re-encode. Do not add a
    parameter or flag that lets a caller disable the backup.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app memory → user's real file on disk | `createWritable()`/`close()` overwrites a real user data file in place; there is no undo |
| browser capability surface | The File System Access API is present on Chromium only; assuming it exists strands other browsers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Repudiation / data loss | `saveInPlaceWithBackup` | mitigate | Backup download is the first statement of the function and has no skip flag; ordering is asserted by a source check in acceptance criteria. Writes are invisible until `close()`, so the backup always completes first. |
| T-04-06 | Denial of service (self-inflicted UX dead end) | `pickTextFileHandle`, `ensureReadWritePermission` | mitigate | Feature-detect at call time and return `null`/`false` instead of throwing; picker `AbortError` (user cancel) is swallowed. Callers always retain the `downloadBlob` path (D-02: never require the API). |
| T-04-07 | Tampering | `downloadBlob` filename | accept | Filenames are derived from the user's own uploaded file name; the browser download layer sanitizes path separators. No server-side filesystem is involved (static SPA). |
| T-04-SC | Tampering | npm installs | mitigate | This plan installs nothing — File System Access, `Blob`, and `URL` are native browser APIs (RESEARCH.md Package Legitimacy Audit: not applicable). Any `npm install` during execution stops for human review. |
</threat_model>
